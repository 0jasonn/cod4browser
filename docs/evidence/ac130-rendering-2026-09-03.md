# AC130 renderer boundary — 2026-09-03

AC130 now produces real cgame-driven world frames in both Release artifacts.
This is **RENDERS** evidence, not playable, mission-complete or Steam-fidelity
evidence. The original Kisak database, game, scripts, camera, entities and FX
drive the scene; no mission progression or gameplay replacement was added.

## Reached defects and changes

- The first CargoShip → AC130 run timed out awaiting its first world frame.
  A direct-map reproduction reached the actual gunship HUD but stopped scene
  submission. Its required DObjs and brushes reached 252,160 vertices and
  500,076 indices before all 32 brushes had been admitted, exceeding the
  browser's 250,000/500,000 dynamic limits. The new 500,000/1,000,000 capacity
  bounds one logical command at 40,000,000 geometry bytes (72-byte vertices,
  32-bit indices). Retained brushes still consume logical occupancy before
  optional FX. Index, finite-value, overflow and atomic-publication checks
  remain unchanged. This capacity change does not preallocate the maximum or
  bound the entire renderer/heap to 40 MB.
- The canonical world has an intentional empty light grid: zero RLE bytes,
  zero entries, one palette, zero bounds and the missing-row sentinel.
  `web_renderer_lighting.cpp` now accepts the precise `R_InitEmptyLightGrid`
  representation. Model fallback selects the canonical palette and returns
  no primary light when default palette entry 1 is absent, matching
  `R_ExtrapolateLightingAtPoint`. All 5,205 static-instance lighting failures
  disappear; the retained atlas has 5,205 entries. Malformed missing storage
  and absent palettes remain rejected.
- The browser frame wrapper now checks `com_errorEntered` after the frame
  body, as native `Com_Frame` does. Before this change, the reached renderer
  error left the host reporting running while server time stopped. With the
  old geometry capacity still in place, the same failure now reached terminal
  Worker error handling with its actual message. The existing disconnect
  cleanup remains the handler for Save and Quit; other errors remain terminal.

All temporary stage instrumentation was removed. The existing retail test now
saves its end-of-window canvas for separate visual inspection.
