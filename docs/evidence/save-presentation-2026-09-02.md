# Save presentation prerequisites — 2026-09-02

The shared SP save menu now reads canonical `SaveHeader` metadata instead of
discarding it. It retains description, map and timestamp, and discovers a
paired profile-relative `.jpg` using the same naming convention as deletion.
Directory enumeration and header/body-length checks run through the canonical
filesystem. Embedded header filenames are never used to construct paths.
Short headers/bodies, wrong versions, unterminated display fields, invalid
paths and overflowing paths are excluded. Invalid timestamps remain blank.

`UI_LoadSavegames` previously filled up to 512 save records into a 256-entry
display index. Loading now respects that existing index capacity without
changing the native UI structure. `UI_DrawSaveGameShot` uses typed records
instead of a hardcoded 64-byte stride, handles absent image names without a
null string copy, and retries pending images. Reload clears its material cache.
Both native and browser raw-image stubs now return null so the shared caller
uses `unknownsave`, rather than accepting a default checkerboard as an image.
The functions live in shared `src/ui/ui_savegames.cpp`; no browser save model
or JavaScript mission state was added.

The native screenshot resampler moved unchanged in algorithm to
`src/gfx_d3d/r_image_resample.cpp`, shared by native, Radiant and web build
inventories. A zero-weight read at the end of exact downsampling previously
dereferenced a pixel beyond the source; that read is now omitted, preserving
RGB output. Native `R_TakeResampledScreenshot` now reads pixels after its
reserved header, matching the subsequent resampling pointer (important for
the TGA levelshot caller, whose header is 18 bytes).

## Remaining screenshot work

This section records the boundary at the prerequisite milestone. The subsequent
[thumbnail milestone](save-thumbnails-2026-09-02.md) implements browser capture,
durable JPEG completion and raw-image upload and lists current limitations.

This is not a completed save-thumbnail implementation. Save commits currently
do not request a screenshot. Browser framebuffer capture, JPEG encoding,
durable completion before Worker shutdown, bounded JPEG decoding and raw
`Material`/`GfxImage` upload remain to be connected. Native raw-image decoding
is also a pre-existing stub. The browser build compiles the shared resampler
but does not yet call it during saving.

Use the native 512x512, quality-90 JPEG convention, canonical profile paths
and save identity. Put asynchronous codec work at the platform boundary;
keep save state and image/material identity in Kisak. Handle overwrite,
deletion, profile changes and shutdown while an encode/decode is pending.
Keep UI fallback active until an actual image is ready. Do not add a second
asset model or expose new production diagnostic APIs.

Dates currently use ISO numeric formatting and 24-hour time. Compare shipped
locale-specific formatting, description localization, screenshot timing,
orientation, gamma and actual displayed thumbnails against Steam before
claiming presentation parity. Verified save metadata and injected Airplane saves do
not establish authored checkpoints, chapter completion or fresh-process
Continue.
